## Overview

KAROSERI is an enterprise auto body repair and modification management system (Bengkel Karoseri & Perbaikan Bodi). It coordinates end-to-end workshop operations from intake estimation to production, quality control, inventory control, and billing across five core roles:
- **Owner / Administrator** (Executive oversight, master settings, audit logs, backup/restore)
- **Service Advisor (SA)** (Vehicle intake, SPK creation, RAB estimation, amendment management)
- **Foreman / Mandor** (7-stage WBS tracking, borongan worker assignments, photo uploads)
- **Warehouse Officer / Petugas Gudang** (Goods issue with RAB quota validation, restock, stock audit logs)
- **Cashier / Kasir** (Down payment recording, final invoice settlement, BAST handover)
- **Customer (Public)** (Read-only real-time SPK progress timeline via `/tracking/:spk_no`)

## Data Flow

1. **Authentication & Session:**
   - User authenticates via Supabase Auth (`LoginPage.tsx`).
   - `AuthContext` resolves user session and fetches profile metadata from `profiles` table.
   - `App.tsx` routes the user to the role-specific dashboard.
2. **Work Order Lifecycle:**
   - **Intake:** SA creates SPK (`SpkForm.tsx`), uploads initial condition photos to Cloudinary, and prepares RAB estimation (`RabCalculator.tsx`).
   - **Approval & DP:** Customer approves; Kasir records Down Payment (`DownPaymentModal.tsx`), transitioning SPK to `ACTIVE`.
   - **Production:** Mandor assigns workers (`SpkBoronganPanel.tsx`), checks off 7 WBS stages (`WbsChecklist.tsx`), and documents progress (`WbsGalleryUploader.tsx`).
   - **Material Requisition:** Warehouse releases materials against RAB quotas via `GoodsIssueForm.tsx`.
   - **Quality Control:** QC Officer conducts final inspection (`QcInspectionForm.tsx`) to set `PASS` status.
   - **Settlement & Handover:** Kasir calculates remaining balance (Base Price + Amendments - DP), issues invoice, confirms payment (`KasirDashboard.tsx`), and generates signed BAST (`BastModal.tsx`).
   - **Public Tracking:** Vehicle owner tracks progress in real-time via `/tracking/:spk_no`.

## Technical Debt

- [ ] **No automated test suite:** Lack of unit tests (Vitest) or component tests for critical financial calculations (RAB, invoice settlement, stock balance).
- [ ] **Orphaned backend dependencies:** `package.json` includes `express`, `cors`, `multer`, and `pg` with a `server` script, but no active `server/` codebase exists in the client-first Vite architecture.
- [ ] **Explicit `any` type casting:** Several complex Supabase query responses and joins bypass strict TypeScript types (e.g., in `KasirDashboard.tsx` and `RabCalculator.tsx`).
- [ ] **Mixed i18n localization:** `react-i18next` is installed and partially configured, but many UI labels remain hardcoded in Indonesian or English.

## Conventions

- **Naming:** PascalCase for React components and pages, camelCase for services, hooks, and utilities.
- **Architecture:** Layered modular structure (`components/`, `pages/`, `services/`, `context/`, `hooks/`, `lib/`, `types/`, `utils/`).
- **Styling:** Tailwind CSS v4 utility classes paired with custom design tokens in `index.css`.
- **Database Access:** Supabase client with PostgreSQL Row Level Security (RLS) enforcement.
